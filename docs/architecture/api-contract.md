# ScaleLink API Contract

Contract version: 1.0
Frozen: 2026-09-15

This document freezes the ScaleLink REST API before implementation
of the application business logic.

Implementation should follow this contract unless a later documented
contract revision is deliberately created.

---

# 1. Link Service

The Link Service owns:

- creation of shortened links
- listing links
- retrieval of individual links
- deletion of links
- short-code resolution
- browser redirects

## General rules

API content type:

    application/json

Target URLs:

- must use http:// or https://
- must be valid URLs
- maximum length: 2048 characters

Short codes:

- generated by the Link Service
- initially 6 characters
- Base62: A-Z, a-z, 0-9
- unique in PostgreSQL

---

## POST /api/links

Creates a shortened link.

Request:

    {
      "target_url": "https://www.example.com/some/very/long/address"
    }

Successful response:

    HTTP 201 Created

    {
      "id": 1,
      "short_code": "abc123",
      "target_url": "https://www.example.com/some/very/long/address",
      "public_url": "http://localhost:8000/r/abc123",
      "created_at": "2026-09-15T12:00:00Z"
    }

Errors:

- 422 if target_url is missing or invalid
- 500 for an unexpected server or database failure

Creating the same target URL more than once is allowed.

---

## GET /api/links

Returns all links.

Successful response:

    HTTP 200 OK

Example:

    [
      {
        "id": 1,
        "short_code": "abc123",
        "target_url": "https://www.example.com/",
        "public_url": "http://localhost:8000/r/abc123",
        "created_at": "2026-09-15T12:00:00Z"
      }
    ]

Links are returned newest first.

---

## GET /api/links/{id}

Returns one link using its numeric database ID.

Successful response:

    HTTP 200 OK

Error:

    HTTP 404 Not Found

when the link does not exist.

---

## DELETE /api/links/{id}

Deletes one link.

Successful response:

    HTTP 204 No Content

Error:

    HTTP 404 Not Found

when the link does not exist.

Associated click events are removed through the PostgreSQL
foreign-key cascade.

---

## GET /r/{shortCode}

Resolves a short code and redirects the browser.

Example:

    GET /r/abc123

Processing:

1. Link Service looks up the short code.
2. Link Service retrieves the target URL and link ID.
3. Link Service reads the HTTP referrer when available.
4. Link Service converts the User-Agent into a coarse category.
5. Link Service sends an event to Analytics Service using REST.
6. Link Service redirects the browser to the target URL.

Successful redirect:

    HTTP 307 Temporary Redirect

Response header:

    Location: https://www.example.com/

Unknown short code:

    HTTP 404 Not Found

Analytics failure does not block the redirect.

The Link Service will use a short timeout when calling Analytics.
If Analytics is unavailable, the destination redirect still occurs.

---

## GET /health

Liveness endpoint.

It checks whether the Link Service process is alive.

It does not check PostgreSQL or Analytics.

Successful response:

    HTTP 200 OK

    {
      "service": "link-service",
      "status": "healthy"
    }

---

## GET /ready

Readiness endpoint.

It checks whether the Link Service can communicate with PostgreSQL.

Successful response:

    HTTP 200 OK

    {
      "service": "link-service",
      "status": "ready"
    }

Failure:

    HTTP 503 Service Unavailable

---

# 2. Analytics Service

The Analytics Service owns click-event recording and statistics.

It does not perform invasive user tracking.

---

## POST /api/events

Records one click event.

This endpoint is intended primarily for calls from the Link Service.

Request:

    {
      "link_id": 1,
      "referrer": "https://www.google.com/",
      "user_agent": "desktop"
    }

referrer may be null.

Allowed coarse user_agent values:

- desktop
- mobile
- tablet
- bot
- other
- unknown

The Analytics Service generates clicked_at on the server.

Successful response:

    HTTP 201 Created

    {
      "id": 1,
      "link_id": 1,
      "clicked_at": "2026-09-15T12:05:00Z",
      "referrer": "https://www.google.com/",
      "user_agent": "desktop"
    }

Errors:

- 422 for invalid request data
- 500 for unexpected server or database failure

---

## GET /api/stats/{linkId}

Returns aggregated statistics for a link.

Successful response:

    HTTP 200 OK

    {
      "link_id": 1,
      "total_clicks": 12,
      "last_clicked_at": "2026-09-15T12:05:00Z"
    }

If there are no clicks:

    {
      "link_id": 1,
      "total_clicks": 0,
      "last_clicked_at": null
    }

---

## GET /health

Liveness endpoint.

Successful response:

    HTTP 200 OK

    {
      "service": "analytics-service",
      "status": "healthy"
    }

---

## GET /ready

Readiness endpoint.

Checks whether Analytics Service can communicate with PostgreSQL.

Successful response:

    HTTP 200 OK

    {
      "service": "analytics-service",
      "status": "ready"
    }

Failure:

    HTTP 503 Service Unavailable

---

# 3. Service-to-Service REST Contract

The Link Service calls:

    POST {ANALYTICS_SERVICE_URL}/api/events

ANALYTICS_SERVICE_URL must come from configuration.

Local example:

    http://127.0.0.1:8001

Kubernetes example:

    http://analytics-service

The Analytics REST call is synchronous but non-critical.

An Analytics outage must not prevent users from following a
shortened URL.

---

# 4. Privacy Boundary

ScaleLink records only:

- link ID
- click timestamp
- HTTP referrer when available
- coarse User-Agent category

ScaleLink intentionally does not record:

- IP addresses
- tracking cookies
- device fingerprints
- user account identities
- precise geographic information
